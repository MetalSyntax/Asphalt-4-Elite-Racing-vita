## Console run #1 result (log 001) and fix

- Hung on the Gameloft logo after skipping the intro video: `CHighGear::GameLoop` state 30 (usleep 1 s, then
  `IsMoviePlaying`) never reached `StopMovie`; the two fixed `PlaybackDidFinish` posts (0.25 s / 1 s) were consumed
  before the game set `isMoviePlaying = 1`. Now `uikit.c run_movie_done` re-posts every 0.25 s until
  `g_sharedMoviePlayerInstance` is cleared by `StopMovie` (max 10 s).
- `video.c` leaked GL state into the game (matrix mode PROJECTION, its own vertex/texcoord pointers, client arrays,
  GL_REPLACE): `gl_save/gl_restore` now cover them and call `gles_reapply_guest()`.
- Expected on run #2: a few `PlaybackDidFinish ... -> 1 observer(s)` lines, then `TRY TO OPEN [textures\splash.bsp]`.

## Console run #3 (log 003 + psp2dmp): root cause found

- Watchdog dump: game thread (`pthread`) waiting in `d_usleep` with **r0 = 0x980F4240**, return address 0x9801F83C
  (GameLoop state 30). `usleep(1000000)`: the literal 0xF4240 at 0x1FDC8 lies inside `__TEXT.__const`, so
  `tools/macho_prep.py` rebased it (+0x98000000) -> a ~42-minute sleep. Hosttest missed it (glibc `usleep(>=1 s)`
  returns EINVAL at once).
- Fix: the `__const` literal branch now honours `numeric_slots`, and `literal_is_number` treats r0 of
  `_usleep`/`_sleep` as a number. Removed 2 words: 0x1FDC8 and 0x41AD0 (0xF81F0, an RGB565 AND mask in the
  color packer at 0x41718). `rebase.bin` = **4817 words**.
